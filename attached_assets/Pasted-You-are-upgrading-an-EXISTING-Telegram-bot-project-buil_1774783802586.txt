==================================================
PART 2 — DELIVERY TRACKING
==================================================

When a broadcast is sent successfully to a user:

- store user_id
- store broadcast_id
- store Telegram message_id
- store sent_at
- if auto_delete_enabled:
    calculate delete_at = sent_at + auto_delete_after_seconds
    set delete_status = pending
  else:
    delete_status can be null or skipped

IMPORTANT:
- Works for text, photo, video broadcasts
- Must not duplicate delivery records for the same send event

==================================================
PART 3 — AUTO DELETE ENGINE
==================================================

Use APScheduler (or the existing scheduler from Broadcast Phase 1).

Add a background deletion job that regularly checks broadcast_deliveries for:
- delete_status = pending
- delete_at <= now
- deleted_at is null

For each eligible record:
1. call bot.delete_message(chat_id=user_id, message_id=message_id)
2. if success:
   - set deleted_at = now
   - set delete_status = deleted
3. if failure:
   - set delete_status = failed
   - store delete_error safely

IMPORTANT:
- Must never crash the bot
- Must handle deleted/missing/forbidden messages safely
- Must continue processing other pending deletions
